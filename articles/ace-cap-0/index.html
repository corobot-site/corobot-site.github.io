PAPER NOTE ｜ 协作机械臂

让 AI 自己写机器人的代码，然后把它冻住

商汤创始人王晓刚任董事长的 ACE Robotics 发布 ACE-CaP-0：由通用 AI Agent 写、测、改控制代码，再冻结成可复用技能。团队自测 240 次真机试验成功 221 次。

文 / Corobot 编辑部2026-11-16阅读 5 分钟协作机械臂

如果每一步都调用大模型，机器人会变慢；如果先把行为写成程序再执行，推理就被复用。ACE-CaP-0 做的是后者——但把「写程序」这件事交给了 Agent。

01 · 它怎么工作

Agent 自己决定什么时候求助，一共三种方式：需要示范时，请人手动带一遍机械臂，同时录下视频、臂轨迹与关键关节位姿；判断有用时才自建一个仿真环境去试程序；最后按真机跑出来的结果改代码。

作者比较了几种组合，发现「按需示范 + 选择性使用仿真」效果最好——也就是说，人的介入与仿真的使用都不是越多越好。

02 · 92.1% 是怎么来的

八项真实任务，包括插充电器、装面包、拧开瓶盖、套杯子、插花、装鞋等。程序冻结之后，240 次真机试验里成功 221 次，成功率 92.1%；其中七项任务达到 90% 以上，插充电器一项 100%。

每个任务的平均执行时间是 0.97 到 2.27 分钟。运行时靠机器人自己的感知与控制，人和编码 Agent 都不在环。

03 · 「冻结」才是关键动作

这条路继承了 Code as Policies 的思路：把机器人行为表达成可执行代码，而不是每一步都调一次大模型。反复调模型会拖慢机器人，而一份写完的程序会把「写它时的推理」复用下去。

难点在于：怎么在不做太多次昂贵真机试验的前提下，把代码调到能用。ACE-CaP-0 的答案是让 Agent 自己判断何时要人示范、何时要仿真、何时该按真机反馈改。

04 · 还没被回答的

结果是团队自选的单一双臂平台、单套任务集，未获独立复现。换一套机械臂、换物体、换光照与背景，成功率会掉多少，论文没有给。

另外，冻结意味着这套技能不能自适应：任务稍变就要重新写一遍。这条路省掉的是推理时间，付出的可能是泛化能力。

难的不是写出一次能跑通的代码，> 是把它冻成明天还能跑的技能。

— ACE-CaP-0 的核心取舍（编辑部概括）
